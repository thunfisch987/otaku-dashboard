# Otaku Dashboard

Operator dashboard for events run by a non-profit youth organization: sell
stock at the counter, track products and money, and publish public preorder
forms. Used on-site by 1–3 trusted operators, so every signed-in user has
access to every feature.

Rules that must not be broken when changing this codebase are in
[AGENTS.md](./AGENTS.md). This file covers layout, setup, and architecture.

## Stack

- **Nuxt 4** (`app/`) with Vue 3 and TypeScript, using `@nuxt/ui` v4 and
  Tailwind.
- **Convex** (`convex/`) for the database, queries, mutations, and actions.
- **Better Auth** (passkey + Google) via `@convex-dev/better-auth`, reached
  through a same-origin `/api/auth` proxy.
- PWA shell, `@tanstack/vue-table` for inventory tables, **Bun** for tooling.

## Requirements

- Bun 1.4.x (`devEngines` in `package.json` pins it).
- Access to a Convex dev deployment, plus `BETTER_AUTH_SECRET`, `SITE_URL`, and
  Google OAuth credentials.

## Environment

`.env.local` is git-ignored and required for anything that talks to Convex,
signs in, or seeds. The variables it needs, grouped by purpose:

- **Convex**: `CONVEX_URL`, `CONVEX_DEPLOYMENT`, `CONVEX_DEPLOY_KEY`,
  `CONVEX_SITE_URL`, `NUXT_PUBLIC_CONVEX_URL`, `NUXT_PUBLIC_CONVEX_SITE_URL`.
- **Auth / site**: `BETTER_AUTH_SECRET`, `SITE_URL`, `NUXT_PUBLIC_SITE_URL`,
  `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`.
- **Dev only**: `ENABLE_DEV_TOOLS`, `DEV_AUTH_EMAIL`, `DEV_AUTH_PASSWORD`.
  Never set these on a production deployment.
- Optional: `NUXT_DEV_ALLOWED_HOSTS` for `dev:tail`.

`.env.local` may also carry unused `DOPPLER_CONFIG`, `DOPPLER_ENVIRONMENT`, and
`DOPPLER_PROJECT`; nothing reads them.

## Setup

```sh
bun install --frozen-lockfile   # plain bun install only when changing deps
cp /path/to/primary-checkout/.env.local .env.local
bunx convex dev                 # own terminal; syncs schema and functions
bun run dev                     # own terminal; http://localhost:3001
```

`bunx convex dev` is a long-running sync watcher. Run it in its own terminal,
separate from `bun run dev`, while editing Convex code.

### Convex deployment environment

`.env.local` configures Nuxt, Nitro, and the Convex CLI, but Convex functions
read variables stored on the deployment. Set the backend variables once per
deployment with `bunx convex env set` (or the dashboard under Settings →
Environment Variables):

```sh
set -a; source .env.local; set +a
bunx convex env set BETTER_AUTH_SECRET "$BETTER_AUTH_SECRET"
bunx convex env set SITE_URL "$SITE_URL"
bunx convex env set GOOGLE_CLIENT_ID "$GOOGLE_CLIENT_ID"
bunx convex env set GOOGLE_CLIENT_SECRET "$GOOGLE_CLIENT_SECRET"
```

Add the optional ones the deployment uses the same way:
`BETTER_AUTH_INITIAL_ADMIN_EMAIL`, `BETTER_AUTH_API_KEY`, `CONVEX_SITE_URL`,
`ENABLE_GOOGLE_AUTH`, `ENABLE_DEV_AUTH_ORIGINS`, and `AUTH_ALLOWED_HOSTS`.
For local dev tooling also set `ENABLE_DEV_TOOLS=true`, `DEV_AUTH_EMAIL`, and
`DEV_AUTH_PASSWORD` here — the dev seed runs inside Convex and cannot read
`.env.local`. Never set those on a production deployment. Keep
`CONVEX_DEPLOYMENT` and `CONVEX_DEPLOY_KEY` local; functions do not need them.

`bunx convex env list` shows what the deployment has. Re-run `env set` for a
variable to change it.

A fresh worktree has neither `node_modules` nor `.env.local`, and both are
git-ignored. Copy the environment from your primary checkout, which is the first
entry in `git worktree list --porcelain`:

```sh
cp "$(git worktree list --porcelain | awk '/^worktree /{print $2; exit}')/.env.local" .env.local
```

Do not copy `node_modules` between checkouts: it is hundreds of megabytes, can be
stale against the branch's lockfile, and installing from Bun's shared cache takes
a few seconds.

## Verifying signed-in surfaces

Operator pages need a real Better Auth session because Convex checks the
session-derived identity on every query — bypassing the route guard renders a
page that cannot load or write data.

1. Set `ENABLE_DEV_TOOLS=true`, `DEV_AUTH_EMAIL`, and `DEV_AUTH_PASSWORD` on
   the Convex deployment (see [Convex deployment
   environment](#convex-deployment-environment)) and in `.env.local`, then
   restart `bun run dev` so the Nuxt route reads them. The seed runs inside
   Convex and only sees the deployment values.
2. Run `bun run seed:dev`. It creates the dev operator plus demo data:
   products at zero and low stock, helper pricing, sales history, an active
   preorder form with submissions. Demo rows use the `[demo] ` product prefix
   (the trailing space is part of it), the `dev-seed-` checkout id, and the
   `dev-demo` form slug, so they never touch real data. Re-seeding recreates the
   operator account, so sign in again afterwards.
3. Open `http://localhost:3001/dev/login?next=/dash/dashboard`. The route exists
   only under `nuxt dev`, requires `ENABLE_DEV_TOOLS=true`, refuses a production
   site URL, and signs in through the normal `/api/auth` proxy so the cookie is
   first-party and the Convex JWT exchange matches a human login.

Public `preorder/[slug].vue` pages need no login.

## Auth architecture

The auth server runs inside Convex, not in Nitro:

- `convex/auth.ts` holds the Better Auth instance and users; `convex/http.ts`
  mounts its HTTP routes; `convex/convex.config.ts` installs the component.
- `app/auth.config.ts` is the browser client, pointed at the same-origin
  `/api/auth` proxy. `crossDomainClient` is deliberately not used — it would
  move the session into `localStorage` and break both the SSR cookie→JWT
  exchange and the client token plugin.
- `nuxt.config.ts` enables the same-origin `/api/auth` proxy for Convex, and
  `@nuxtjs/better-auth` runs in `clientOnly` mode so it adds no server routes.
- `server/auth.config.ts` is an unused scaffold kept only so the module does not
  regenerate it.
- Both `convex/auth.config.ts` and the client config must agree on the provider;
  changing one alone silently breaks sign-in.

## Data model

| Table                           | Purpose                                                  |
| ------------------------------- | -------------------------------------------------------- |
| `products`                      | stock, price, helper price, supply cost, supplier        |
| `productCategoryPricing`        | shared Onigiri price and helper price                    |
| `sales` / `saleItems`           | committed checkout header + authoritative lines          |
| `preorderForms`                 | slug, event date, close time, active flag                |
| `preorderFormItems`             | curated menu with product-name and supply-cost snapshots |
| `preorderSubmissions`           | one row per submitter, with items snapshot               |
| `preorderSubmissionItems`       | authoritative submission lines                           |
| `preorderFormStats`             | per-form counters                                        |
| `preorderFormSubmissionWindows` | rate/idempotency windows                                 |
| `preorderFormTotals`            | cached form totals                                       |
| `userAvatarCache`               | cached avatar bytes; Better Auth owns profile data       |

`sales.itemsSnapshot` and `preorderSubmissions.items` are bounded read
snapshots for list views; the child tables stay authoritative for history,
totals, and reverts, and older rows without snapshots fall back to them.
